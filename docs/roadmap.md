# wakeup-alarm ロードマップ

## 進め方

- マイルストーンは develop から main へマージする単位にする。層ごと (DB だけ、画面だけなど) ではなく、薄くても端から端まで動かして確認できる単位で区切る
- 完了条件をすべて満たしたら、リリース前のコードレビューを経て main へマージする
- 完了条件の確認の手段 (自動テスト、AVD、ユーザーに頼む実機・Echo Dot の確認) は、`app/CLAUDE.md` と `alexa-skill/CLAUDE.md` の「動作確認」を参照する。先頭に `実機:` が付いた項目はユーザーに頼む確認
- Alexa 連携は、構成の前提だけを M0 で先に確かめ、本体はアプリの基本ができた後 (M7・M8) に行う
- 順番と区切りは案。進めながら見直す

## M0: Alexa の定型アクションから自作スキルを起動できる

起動すると決まった文を読み上げるだけのスキルを、「アレクサ、おはよう」の定型アクションから起動できる。Alexa 連携の構成の前提を、アプリ側を作る前に確かめる。

### 実施すること

- リポジトリをモノレポの形 (`app/`・`alexa-skill/`・`docs/`) で用意する
- Alexa-hosted スキル (Node.js) を作成し、起動すると決まった文を返す LaunchRequest のハンドラを書く
- モノレポの `alexa-skill/` から Alexa-hosted スキルへデプロイする手順を決め、`alexa-skill/CLAUDE.md` に書く
- Alexa アプリで、フレーズ「おはよう」→ 自作スキルの起動、の定型アクションを作る

### 完了条件

- [ ] LaunchRequest に決まった文を返すことをテストで確かめている
- [ ] `alexa-skill/` の変更を、決めた手順で Alexa-hosted スキルへデプロイできる
- [ ] 実機: 開発者コンソールのテスト画面で、スキルを起動すると決まった文が返る
- [ ] 実機: 開発ステージのスキルが、Alexa アプリの定型アクションの「スキル」→「あなたのスキル」に表示される
- [ ] 実機: Echo Dot に「アレクサ、おはよう」と話しかけると、決まった文が読み上げられる

確かめられなかった場合 (定型アクションに表示されない、起動できない) は、M7・M8 の構成を見直してから先へ進む。

## M1: 単発アラームが1つ鳴って止まる

仮の画面で時刻を指定した単発アラームを1つ登録でき、指定時刻に鳴って「停止」で止まる。データの保存はまだしない。

着手前に、minSdk、アプリケーション ID、過去の時刻を指定したときの扱いを決める。

### 実施すること

- `app/` に Flutter プロジェクトを作成し、Riverpod・drift・`alarm` パッケージを導入する
- lint とフォーマッタの設定
- AVD `Pixel_6a_API_37` の用意
- 時刻を指定してアラームを1つ登録する仮の画面
- 初回起動時に通知の許可を求める

### 完了条件

- [ ] `flutter analyze` と `flutter test` が通る
- [ ] アプリ前面で、指定した時刻に鳴り、鳴動画面の「停止」で止まる
- [ ] ロック中・消灯中に、指定した時刻に全画面の鳴動画面が出て鳴る
- [ ] アプリを終了させた状態でも、指定した時刻に鳴る
- [ ] 端末を使用中に鳴ったとき、通知の「停止」で止まる
- [ ] 過去の時刻を指定したとき、決めた扱いになる
- [ ] 実機: 消灯・ロック中に全画面の鳴動画面が出て鳴り、「停止」で止まる

## M2: グループを登録・保存して鳴らせる

本命＋予備のグループを登録・保存でき、それぞれの時刻に鳴る。繰り返しはまだなく、1回きりのグループとして扱う。

着手前に、予備の数の上限と本命より前の時刻の予備を許すか、2つのアラームの鳴動が重なったときの扱いを決める。

### 実施すること

- drift の DB 定義 (AlarmGroup・AlarmItem) とリポジトリ
- グループの一覧画面と編集画面
- DB の内容を `alarm` パッケージに登録する処理 (再同期の最初の形)

### 完了条件

- [ ] グループを作成・編集・削除・有効/無効の切り替えができ、アプリを再起動しても残っている
- [ ] グループが0件のとき、一覧画面に空であることと登録の導線が表示される
- [ ] 保存したグループの本命と予備が、それぞれの時刻に鳴る
- [ ] グループの時刻を編集すると新しい時刻に鳴り、古い時刻には鳴らない
- [ ] 削除・無効化したグループのアラームは鳴らない
- [ ] 2つのアラームの鳴動が重なったとき、決めた扱いになる
- [ ] グループとアラームの保存・読み込みをテストで確かめている

## M3: 「起きた」で当日の予備がオフになる

一覧画面の「起きた」を押すと、そのグループの当日の残りの予備が鳴らなくなる。

着手前に、「起きた」を押せる期間、一覧画面での「起きた」の見せ方、「その日」の区切り (日付をまたぐグループの扱い) を決める。

### 実施すること

- SkipRecord の DB 定義 (M7 で使うオフの範囲も、この時点で持たせる)
- 一覧画面の「起きた」ボタン
- スキップ判定と、当日の残りの予備の登録の取り消し

### 完了条件

- [ ] 本命が鳴って止めたあと、一覧画面の「起きた」を押すと、そのグループの当日の残りの予備が鳴らない
- [ ] 「起きた」を押したグループ以外のグループは、通常どおり鳴る
- [ ] 「起きた」を押したあとにアプリを終了・再起動しても、当日の残りの予備は鳴らないまま
- [ ] 当日の予備が残っていないときや「起きた」を押せる期間の外では、決めた見せ方になる
- [ ] 鳴動画面と通知には「起きた」が出ない
- [ ] スキップ判定 (日付をまたぐグループを含む) をテストで確かめている

## M4: 曜日の繰り返しと再同期

指定した曜日に毎週鳴り、アプリを開かない日が続いても、端末を再起動しても鳴り続ける。

着手前に、何日先までアラームを登録しておくか、繰り返しなしのグループが鳴った後の扱いを決める。

### 実施すること

- グループの編集画面に曜日の指定を追加
- 鳴動日時の展開と、数日先までの登録
- アプリの起動時・データの編集後・鳴動の通知を受けたときの再同期

### 完了条件

- [ ] 指定した曜日にだけ鳴り、それ以外の曜日には鳴らない
- [ ] 「起きた」を押した翌日は、予備も通常どおり鳴る
- [ ] アプリを開かずに通知の「停止」だけで数日過ごしても、次の鳴動が登録されていて鳴る
- [ ] 端末を再起動したあとも鳴る
- [ ] 繰り返しなしのグループが鳴ったあと、決めた扱いになる
- [ ] 鳴動日時の展開 (週・月・年をまたぐ場合を含む) をテストで確かめている
- [ ] 実機: 繰り返しを設定したグループが、一晩おいた翌朝に鳴る

## M5: 鳴り方と見た目の設定

グループごとに着信音とバイブを選べ、アプリのテーマ (端末の設定に従う／ライト／ダーク) を切り替えられる。

着手前に、着信音の選択方法と、アプリ全体の設定の保存先を決める。

### 実施すること

- グループの編集画面に着信音とバイブの設定を追加
- 設定画面とテーマの切り替え

### 完了条件

- [ ] グループごとに選んだ着信音で鳴る
- [ ] 選んだ着信音が見つからないときも、無音にならずに鳴る
- [ ] バイブのオン・オフがグループごとに反映される
- [ ] テーマを「ライト」「ダーク」に切り替えると、すぐに画面に反映され、アプリを再起動しても保たれている
- [ ] テーマが「端末の設定に従う」のとき、端末のダークモードを切り替えるとアプリの見た目も切り替わる
- [ ] 実機: 選んだ着信音とバイブで鳴る

## M6: 権限の案内と実運用

必要な権限が欠けているときにアプリが気づいて案内でき、Pixel 6a で毎朝の起床に使える状態になる。

着手前に、鳴動を自動で止めるまでの時間と、通知をスワイプしたときに鳴動を止めるかを決める。

### 実施すること

- 権限の確認画面 (通知・正確なアラーム・全画面表示)
- 電池最適化の除外の案内
- 鳴動の自動停止と、通知のスワイプ時の扱い

### 完了条件

- [ ] 通知の権限が未許可のとき、アプリ内で案内が出て、該当の設定画面を開ける
- [ ] 正確なアラーム・全画面表示の権限が未許可のときも、同様に案内が出て設定画面を開ける
- [ ] すべての権限が許可済みのときは、案内が出ない
- [ ] 電池最適化の除外を案内し、設定画面を開ける
- [ ] 鳴動の自動停止と通知のスワイプが、決めた扱いになる
- [ ] 実機: 数日間、実際の起床に使い、鳴らない・止まらないなどの不具合が出ない

## M7: FCM を受けて当日のアラームをオフにし、結果を Firestore に書く

FCM の高優先度データメッセージを受けると、アプリが起動していなくても対象グループの当日の未鳴動のアラームをオフにし、結果を Firestore に書き込む。スキルはまだつながず、テスト用の送信手段から確かめる。

着手前に、対象グループの指定方法と、アプリとスキルの取り決めの具体的な名前と値 (alexa-integration.md に書く)、Firebase の設定ファイルと環境変数の値の管理方法を決める。Firebase プロジェクトの作成 (請求先アカウントは紐づけない) はユーザーが行う。

### 実施すること

- firebase_messaging のバックグラウンドハンドラの中から、drift の DB と `alarm` パッケージを使えるかを最初に確かめる
- Firebase の匿名認証と、FCM トークンの Firestore への登録 (トークンの更新時にも登録し直す)
- FCM を受けて SkipRecord (範囲：未鳴動の全アラーム) を書き込み、再同期する処理
- 処理結果の Firestore への書き込みと、Firestore のセキュリティルール
- テスト用に FCM を送信する手段 (`alexa-skill/` の送信処理を手元から呼ぶなど)

### 完了条件

- [ ] アプリを終了させた状態で FCM を受けると、対象グループの当日の未鳴動のアラームが鳴らなくなり、オフにした件数が Firestore に書き込まれる
- [ ] Doze 中の端末でも、FCM を受けて同じ処理が行われる
- [ ] 鳴動中に FCM を受けても、鳴動中のアラームは止まらない
- [ ] 対象のアラームが当日に残っていないとき、0件として Firestore に書き込まれる
- [ ] オフにした翌日は、対象グループのアラームが通常どおり鳴る
- [ ] 同じリクエスト ID の FCM が2回届いても、処理は1回だけ行われる
- [ ] FCM トークンが更新されると、Firestore の登録も新しいトークンに変わる
- [ ] 匿名認証していない書き込みが、セキュリティルールで拒否されることを確かめている
- [ ] スキップの範囲 (予備のみ／未鳴動の全アラーム) の判定をテストで確かめている
- [ ] 実機: 消灯して一晩おいた状態で FCM を送ると、当日の未鳴動のアラームがオフになる

## M8: 「アレクサ、おはよう」で当日のアラームがオフになり、結果が読み上げられる

M0 のスキルを本体に置き換え、Echo Dot への呼びかけから、アプリの処理、結果の読み上げまでがつながる。

### 実施すること

- スキルの LaunchRequest で、リクエスト ID を発行し、Firestore から FCM トークンを読んで FCM を送る処理
- Firestore の処理結果を約6秒間確かめ、結果に応じて読み上げる処理
- サービスアカウントの鍵を環境変数から読み込む設定

### 完了条件

- [ ] アプリから結果が届いたとき、「今日のアラームを○件オフにしました」と応答することをテストで確かめている
- [ ] 0件の結果が届いたとき、「今日オフにするアラームはありません」と応答することをテストで確かめている
- [ ] 待つ時間のうちに結果が届かないとき、「スマホから応答がありません」と応答し、Alexa の応答の制限時間を超えないことをテストで確かめている
- [ ] FCM トークンが登録されていないときや FCM の送信に失敗したときも、エラーにならずに応答することをテストで確かめている
- [ ] スキルのテストは Firestore と FCM をモックにして、外部にアクセスしない
- [ ] サービスアカウントの鍵がリポジトリに含まれていない
- [ ] 実機: Echo Dot に「アレクサ、おはよう」と話しかけると、対象グループの当日の未鳴動のアラームがオフになり、件数が読み上げられる
- [ ] 実機: Pixel 6a の Wi-Fi を切った状態で話しかけると、「スマホから応答がありません」と読み上げられる
- [ ] 実機: 数日間、朝の「アレクサ、おはよう」に使い、オフにした翌日は通常どおり鳴る
