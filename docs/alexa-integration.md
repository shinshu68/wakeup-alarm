# Alexa 連携：「アレクサ、おはよう」で当日のアラームをオフにする

このファイルは、アプリ (`app/`) とスキル (`alexa-skill/`) の間の取り決めの唯一の正とする。両側の実装は、この「アプリとスキルの取り決め」に合わせる。

## 概要

家の Echo Dot に「アレクサ、おはよう」と話しかけると、対象のグループのアラームのうち、当日まだ鳴っていないものをオフにする。処理結果は Alexa が読み上げる。

アラームの鳴動を止める機能ではなく、未来のアラームを当日分だけオフにする機能である。

## 仕様

| 項目 | 内容 |
| --- | --- |
| 呼びかけ | 「アレクサ、おはよう」(Alexa アプリの定型アクションで設定) |
| 対象グループ | 定型アクションから呼ぶ1グループに固定する (指定方法は未決) |
| 対象のアラーム | 対象グループのうち、当日の予定でまだ鳴っていないもの (本命・予備の両方) |
| 鳴動中のアラーム | 止めない |
| 影響範囲 | 当日分だけをオフにする。翌日以降に予定されたアラームは変更しない |
| 想定する使用タイミング | 当日の朝 |
| 完了通知 | 処理結果を Alexa が読み上げる |

スヌーズは現時点でやらないことに入れている。スヌーズを実装する場合も、鳴動中のアラームのスヌーズはオフの対象にしない。

### 読み上げのパターン

| 状況 | 読み上げ (例) |
| --- | --- |
| 成功 | 「今日のアラームを○件オフにしました」 |
| 対象のアラームがない | 「今日オフにするアラームはありません」 |
| 制限時間内にスマホから応答がない | 「スマホから応答がありません」 |

### アプリの「起きた」との違い

| | 「起きた」 | Alexa の「おはよう」 |
| --- | --- | --- |
| 操作する場所 | ロック解除後のアプリ画面 | Echo Dot への呼びかけ |
| 対象 | 押したグループの当日の残りの予備 | 対象グループの当日の未鳴動のアラーム (本命を含む) |

どちらも「当日だけ鳴らさない」記録を残す仕組みは共通にする (下の「当日だけオフにする仕組み」)。

## 構成

```
Echo Dot
  │「アレクサ、おはよう」
  ▼
Alexa 定型アクション (フレーズ「おはよう」→ アクション: 自作スキルの起動)
  │ LaunchRequest
  ▼
自作スキル (Alexa-hosted スキル / Node.js)
  │ 1. リクエスト ID を発行
  │ 2. FCM の高優先度データメッセージを送信 (ID を含む)
  ▼
Android アプリ (Flutter / firebase_messaging のバックグラウンドハンドラ)
  │ 3. 対象グループの当日・未鳴動のアラームをオフにし、alarm パッケージの登録を組み直す
  │ 4. ID と結果 (件数・成否) を Firestore に書き込む
  ▼
Firestore
  ▲
  │ 5. スキルが ID の結果を約6秒間確認し続け、見つかったら読み上げる
自作スキル
```

### 構成要素

- **Alexa カスタムスキル**
  - Alexa-hosted スキルで作る。開発ステージのまま、自分のアカウントの Echo だけで使う (認定・公開はしない)
  - 定型アクションからはスキルの起動 (LaunchRequest) だけを使う
    - カスタムタスク (スキルの特定機能を定型アクションから直接呼ぶ仕組み) を使う方法は、定型アクションに表示するのに認定・公開が必要なため採用していない
  - スキルの応答には約8秒の制限があるため、結果を待つのは6秒程度にする
- **FCM (Firebase Cloud Messaging)**
  - 高優先度のデータメッセージを使い、Doze 中やアプリ未起動でも処理できるようにする
  - 送信先の FCM トークンはアプリから Firestore に登録し、スキルはそこから読み取る
    - トークンを固定値でスキルに持たせる方法は、トークンが更新されることがあるため採用していない
- **Firestore**
  - アプリからの処理結果の受け渡しに使う。FCM と同じ Firebase プロジェクトにまとめる
  - アプリは Firestore の SDK で書き込み、スキルは Admin SDK で読み取る
  - 書き込みは Firebase の匿名認証とセキュリティルールで、自分のアプリからだけに制限する
- **秘匿情報**
  - スキル側で使う Firebase のサービスアカウントの鍵は環境変数で管理し、コードやリポジトリに含めない

### 当日だけオフにする仕組み (案)

- オフにした日付をグループごとに記録し、その日付の分だけ鳴らさない。アラームの設定そのものは変更しないので、翌日以降は何もしなくても通常どおり鳴る
- 「起きた」で使う SkipRecord に、オフの範囲 (予備のみ／未鳴動の全アラーム) を持たせて、Alexa からのオフにも使う案とする
- アプリは記録を書き込んだあと、plan.md の「アラームの登録」と同じ再同期で `alarm` パッケージの登録を組み直す

### バックグラウンドでの処理 (案)

- firebase_messaging のバックグラウンドハンドラは、アプリ本体とは別の isolate で動く。この中から drift の DB と `alarm` パッケージを使えるかが、アプリ側の前提になる。M7 の最初に確かめる
- FCM のメッセージは同じものが2回以上届くことがあるため、同じリクエスト ID の処理は1回だけにする

## アプリとスキルの取り決め

以下の名前と値は、アプリとスキルの両方でそろえないと、エラーが出ずに動かなくなる。変えるときは、このファイル → 提供する側 → 利用する側の順に直す。どのファイルとどのファイルでそろえるかは、実装したらルートの CLAUDE.md に対で書く。

具体的な名前は M7 の着手時に決め、ここに書く。決める項目は次のとおり。

- **FCM のデータメッセージ** (スキル → アプリ)：種別を表すキー、リクエスト ID のキー
- **FCM トークンの登録先** (アプリ → スキル)：Firestore のコレクション名・ドキュメント ID・フィールド名
- **処理結果** (アプリ → スキル)：Firestore のコレクション名、ドキュメント ID (リクエスト ID を使う案)、フィールド名 (オフにした件数、成否、エラーの種類など)
- **時間**：スキルが結果を待つ時間 (6秒程度)、結果を確かめる間隔
- **処理結果の後片付け**：古い処理結果のドキュメントを消すか、残すか

## 費用

個人で1日1回使う程度なら、すべて無料の範囲に収まる。

| サービス | 扱い |
| --- | --- |
| Alexa 開発者アカウント | 無料 |
| Alexa-hosted スキル | スキルが使う Lambda はリクエスト数の上限なしで無料 |
| FCM | Firebase の無料プロダクト |
| Firebase 匿名認証 | 無料 |
| Firestore | Spark プラン (無料) で1日あたり読み取り5万回・書き込み2万回まで。今回の使い方では1回あたり読み取り十数回・書き込み1回程度 |

### 注意点

- Firebase プロジェクトに請求先アカウントを紐づけない。紐づけると自動で従量課金の Blaze プランに切り替わる。Spark プランのままなら、上限を超えても課金されずにサービスが止まるだけ
- そのため、Blaze プランが必要な機能 (Cloud Functions など) は使わない
- Google Play には公開しない (公開には開発者登録の登録料がかかる)。自分のスマホに直接インストールして使う

## 最初に確かめること

開発ステージのスキルが、Alexa アプリの定型アクションの「スキル」→「あなたのスキル」に表示され、フレーズ「おはよう」から起動できるかを実機で確かめる。この構成の前提になるため、アプリ側を作る前に、起動すると決まった文を返すだけのスキルで試す (roadmap.md の M0)。
